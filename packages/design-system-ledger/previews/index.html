ZKCVP Ledger

A second visual language over the same domain. Where the first direction reads like a forensic tool at 2am, Ledger reads like a countersigned document: light-first, ink on paper, square ruled structure, a real measure for prose, and a compact density context for the developer's data surfaces rather than compactness as the default.

Requirements, verdicts, sealed evidence, log references and commits. Each one encodes a rule that keeps a surface from saying something false.

What changed, and why

The accent moved from amber to ink blue

Amber is a light fill, so it needed a separate value for text and for backgrounds in both themes, and white text on it fails contrast at any size. This blue clears 7.6:1 as text on paper and as a fill under white text, so light mode needs only one value and the checkbox tick needs only one glyph. Blue also frees the verdict family from having to avoid it.

A negative verdict is set in ink, not in a hue

The first direction gave not_satisfied its own periwinkle so it would not read as an error. Ledger removes the hue entirely and renders it as a solid ink chip. It cannot sit near the red reserved for things that actually broke, it survives greyscale and colour-blind rendering, and it is honest about weight: a negative verdict is the most emphatic recorded fact on the page.

Role identity lost its colour on purpose

Stakeholder and developer were blue and slate. Blue is now the accent, so they could not keep it, and dropping hue turned out to express the underlying rule more strongly than any pair of colours did: who someone is must never be confused with what an evaluation concluded, so identity is the one thing in this system that is never coloured.

Density became a context instead of two row tokens

The first direction shipped a dense row height and a comfortable one side by side, and every component had to pick. Here the comfortable values are the default and [data-density="compact"] re-points the same tokens, so a commit table can be dense inside a page that is not, and no component needs to know which mode it is in. The switch above changes every specimen on every page.

The domain rules did not change at all

eval_failed still renders as "Not satisfied". Sealed evidence still keeps its verify action live. An inclusion proof still carries the sentence saying it does not prove the judgment was correct. Digests are still truncated in the middle. components/types.ts is byte-identical to the first direction's copy, deliberately: two visual languages over one domain, and if that file ever diverges, one of the two is misinforming someone.

Running the React gallery

These pages are hand-written markup, so they prove the stylesheet works without a build step. The React gallery renders the same system through the actual TSX components, and is the surface to check when changing a component rather than a class. 

cd design-system-ledger
npm install
npm run dev        # gallery at http://localhost:5173
npm run typecheck  # components + gallery, strict
